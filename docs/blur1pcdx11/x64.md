## Building and running

Configure with `-A x64` into `_work/build/vs`. Until `tools/build.sh` can select the architecture (it is authored in Blur1PC and hard-codes `-A Win32`; see decisions), the build is `tools/build.sh` with `-A x64`: `_work/t244/build64.sh` in this worktree. Judge it by errsum's error count, then copy `Amax.exe`/`Amax.pdb` from `_work/build/vs/Release` and the generated `_work/build/gen/fx11/effects` (as `fx11/`) to `_work/run`.

Beside the exe the game needs only `fx11/` (native effects); `Amax.pdb` and a `logcfg.xml` naming this worktree's `_work/run/amax.log` are optional. Audio output is DirectSound (Blur1PC T144); the exe has no OpenAL reference, and the OpenAL import library still listed in `blur_common.cmake` contributes nothing to it. The exe imports `d3d11`, `dxgi`, `d3dcompiler_47`, `dsound` and the x64 VC++ runtime, and no D3D9 or D3DX9 DLL. `play.bat` starts it as before.

Prerequisite outside the tree: x64 OpenSSL 0.9.8i for DemonWare's libcurl (`_work/vendor_x64/openssl-x64`), built from the official tarball (SHA1 `b2e029cfb68bf32eae997d60317a40945db5a65f`) with `tools/demonware_cmake/build_openssl_x64.cmd <src> <install>`.

## Pointer width: what changed and why

On x64, `U32`, `DWORD`, `long` and `int` stay 32-bit, while pointers become 64-bit. `/we4311 /we4302` make pointer truncation a build error in this branch. `INTPTR` (`core/Core.h`) is now pointer-sized; it is `unsigned int` on x86, so x86 semantics are unchanged. Every edit is tagged `[Blur2PC][x64]`.

Formats and structures:

- **FX sampler parameters** (`nglFXParam_Sampler::Texture`) occupy two words in every converter-built ParameterData block, so the texture word cannot widen without moving every baked offset. On x64 it holds a slot from `Core::PointerToSlot32` (`core/utility/PointerSlot32.h`). That registry assigns one slot per distinct address and never reuses it, so a stale slot means what a stale pointer meant; on x86 the slot is the pointer itself.
  - **Writers:** the shared/default texture setup, `FX::SetParameter`, `System::SetParameter`, and `Context::SetTextureParameterImmediate`/`SetParameterImmediate`.
  - **Readers:** `Context::SetTexture`/`SetVertexTexture`, which were previously compiled only at `WORD_SIZE == 32`, and NativeFX11 binding.
  - **Texture parameter API:** a texture value always points at a texture pointer.
- **Material `TEXTURE_PTR`** elements are pointer-sized on x64. They are created only at runtime (`ExposeParameter`); exported material data carries 4-byte layouts, and reading a `TEXTURE_PTR` from a file asserts. No retail file is known to contain one; that is unverified.
- **Lock-free job queue** (`jobqueue_task_queue_lf`): the pointer and its 32-bit change count form a 16-byte pair updated with `cmpxchg16b`, keeping the ABA protection. `Task::ParamData` is 96 bytes, 8-aligned on x64, because jobs copy structs of pointers into it. Two jobs passed `&p, 4` for a pointer.
- **BlockAllocator page table**: two-level, one bitmap per 4 GB of the 47-bit address space. The flat table covered 4 GB, or 8 GB in an untested `WIN64` branch.
- **UI sprites**: `C_Sprite` is 136 bytes on x64 (pointer user data and callback). Retail clears each new sprite with `DCBZ128`, a 128-byte cache-line clear that on PC zeroes the aligned line. On x64 that clear erased the end of the previous sprite, which made text and polygon shapes disappear piecemeal. x64 clears exactly `sizeof(C_Sprite)`.
- **Pointer-sized user data:** sprite/font user data, the audio `HandleCollection` resources, the audio allocator header, actor handle user data and the thread-creation parameter.

Silent 32-bit accesses that no warning catches, all switched to `INTPTR`:

- **Particles:** `Spu::Set((U32*)&ptr, (U32)ptr)` writes, the atomic pools, and the spawning emitters.
- **Gravity:**
  - shape pointer reads;
  - the contact-stream write pointer, which needs a 64-bit `AtomicAdd` added for PC;
  - mesh body arrays read with a 4-byte stride.
- **Job kernel:** group pool and dependency reads.
- **Pointer-select tricks:** portal/BSP/camera masks and `Select`.
- **Alignment masks** such as `& 0xfffffff0` / `& ~U32`.

Other x64 incompatibilities:

- The crash handler uses `Rip`/`Rbp`/`Rsp` and `AMD64` stack walking.
- `RaiseException` thread naming uses `ULONG_PTR`.
- DemonWare's crypto provider handle is now `HCRYPTPROV`.
- The engine's `WIN64` branch expected `__binary_*` symbols from a binary-to-object tool. This build defines `_binary_*` C arrays, so both architectures use the x86 names.

Retail quirks preserved:

- `SpDataFinder` passes the race-type string pointer that x86's `(const)` cast carried.
- The blindfire sentinel compares against the low 32 bits of `Maths::Constants<U32>::Max`'s address, as retail compared against the full address.

- **RenderingData resource allocator** (`archive.cpp` `g_sizes`): the retail block areas (16/48/96 bytes) fit x86 object and pointer-array sizes; on x64 a 13-entry vertex-buffer pointer array is 104 bytes, and any size above the largest area indexed one past the area array (`BlockAllocator::SizeToAreaIndex`), crashing in `Area::AllocateBlock` during model loading (seen in the user's own run). The x64 areas are 32/96/192 and `BlockAllocator::Allocate` asserts and returns NULL for sizes above the largest area.

Known latent items, not reached in the tested build:

- Audio components sit at 4 mod 8 after their type tags; this is misaligned but works.
- `ENABLE_GUARD_BLOCKS` headers overlap on x64; the feature is off.
- MemoryTracker callstack dumps read pointer arrays as 32-bit; this is dormant.
- The mutex-based job queue (`JQ_USER_LF_QUEUE` 0) still uses 32-bit node access.

## Lower-phase fault found here: T245 (Blur1PCDX11)

`C_D3D11GameDevice::SetVertex/PixelShaderConstantF` guarded `start + count > 256`. A parameter missing from a shader has `m_RegisterIndex == UINT_MAX`, and `UINT_MAX + 1` wraps to 0, so every DX11 build wrote 16 bytes before the native constant arrays whenever the UI set light constants a shader does not declare (e.g. light-paint rendering). x86 wrapped back into the preceding array silently; x64 faulted. The guard is now `start >= 256 || count > 256 - start`.

Committed on `blur1pcdx11` as 0cb00815, merged into the HDR child (4a467ae2) and from there into this branch.

The rule applied on this branch: a named host, share, mapped tools drive, internal URL, internal e-mail address or source-control binding is removed; where code needs a value, it gets the local equivalent the code already supports or an empty default that must be configured.
